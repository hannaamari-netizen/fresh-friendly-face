# Haya Al-Salat — App Privacy Mapping for App Store Connect

Use this document to answer **App Store Connect → App Privacy** accurately. It maps every data type collected or processed by Haya Al-Salat to Apple's privacy categories.

---

## Data types collected by the app

| Apple category | Data type | Purpose | Linked to user identity | Used for tracking | Notes |
|---|---|---|---|---|---|
| **Location** → Coarse Location | Approximate latitude/longitude | Calculate local prayer times via the Aladhan API | No | No | Only used while the app is in use; not stored permanently |
| **Identifiers** → User ID | Supabase `auth.users` UUID | Sync preferences across devices if signed in | Yes | No | Only present when the user signs in |
| **Identifiers** → Device ID | Push notification token | Deliver Fajr reminders and prayer-time notifications | No | No | Generated by APNs; rotated on reinstall |
| **Usage Data** → Product Interaction | Button taps, settings changes | Improve UX and debug flows | No | No | Currently stored locally; not sent to analytics services |
| **User Content** → User preferences | Reminder message, snooze duration, fade-in duration, Adhan/recitation volume | Persist user settings | No | No | Stored in local device storage and Supabase if signed in |

---

## Data the app does NOT collect

The following Apple categories are **not used** by Haya Al-Salat:

- Financial information
- Contact information (name, email, phone) except via auth provider
- Contacts
- Photos or videos
- Audio (microphone)
- Camera
- Health and fitness
- Sensitive information
- Browsing history
- Search history
- Device diagnostics (crash data only if a future crash reporter is added)

---

## Required reason APIs

Apple requires a declared reason for certain APIs. Haya Al-Salat does **not** use any of the following:

- File timestamp APIs
- Disk space APIs
- System boot time APIs
- Active keyboard APIs
- User defaults APIs beyond standard `localStorage`/Capacitor Preferences

Therefore, no additional Required Reason declarations are needed in the app's `PrivacyInfo.xcprivacy` beyond what Capacitor ships.

---

## Third-party SDK privacy manifests

The native iOS project depends on Capacitor and its plugins. Each plugin includes its own `PrivacyInfo.xcprivacy` manifest where required by Apple. Do not remove these files from `ios/App/Pods/` or the generated Xcode project.

| SDK / Plugin | Privacy manifest location |
|---|---|
| Capacitor core | `node_modules/@capacitor/ios/Capacitor/PrivacyInfo.xcprivacy` |
| Capacitor Push Notifications | bundled via CocoaPods |
| Capacitor Local Notifications | bundled via CocoaPods |
| Capacitor Splash Screen | bundled via CocoaPods |

## App Store Connect answers

### Data collection

**Does your app collect data from this device?** → **Yes**

### Data types to declare

Select the following in the App Privacy questionnaire:

- [x] Location → Coarse Location
- [x] Identifiers → User ID
- [x] Identifiers → Device ID
- [x] Usage Data → Product Interaction
- [x] User Content → Other User Content (preferences/settings)

### Tracking

**Does your app track users?** → **No**

Tracking, as defined by Apple, means linking data collected from the app with third-party data for advertising or sharing with a data broker. Haya Al-Salat does not do this.

### Required reasons

No additional required-reason declarations are needed.

### Privacy Nutrition Label

The label should read similarly to:

> **Data Used to Track You:** None
>
> **Data Linked to You:** User ID
>
> **Data Not Linked to You:** Coarse Location, Device ID, Product Interaction, Other User Content
